# 2주차: UCI HAR 행동 분류 실험 기록

스마트폰 센서의 128시점·9채널 신호로 6가지 행동을 분류합니다. [최초 CNN 실습](../01_UCI_HAR_CNN.ipynb)의 오류를 확인하고, E 실험으로 구조와 학습 설정을 바꾼 뒤 S 실험에서 `SITTING`/`STANDING` 혼동을 다룹니다. 실험 코드는 당시 작성한 버전을 유지하고, 각 번호의 목적을 노트북 마크다운에 덧붙였습니다.

## 수정 작업 계획과 적용 내용

1. 최초 실습의 번호별 작업을 설명하고, 기존 실행 결과는 원래 셀에 보존합니다.
2. E0부터 S3까지 각 버전의 코드 번호를 독립된 셀로 나눠 앞에 목적과 확인할 점을 적습니다. 이전 코드 순서와 최종 테스트 보호 셀을 보존합니다.
3. 어떤 변경을 시도했는지, 관찰된 결과와 아직 검증되지 않은 가설을 아래 표에 구분합니다.
4. 파일 구조와 코드 문법을 검증한 뒤 Git에 커밋합니다. Colab 재실행과 추가 시드 실험은 별도 후속 작업입니다.

## 실험 순서

| 파일 | 변경과 확인하려는 점 | 현재 기록 상태 |
|---|---|---|
| [01 기본 CNN](../01_UCI_HAR_CNN.ipynb) | 9채널 Conv1D, 20에폭, 초기 혼동 행렬 확인 | 노트북에 원래 실행 출력 있음. 피험자 단위 검증 전의 결과 |
| [E0](CNN_UCI_HAR_E0.ipynb) | 학습 피험자와 검증 피험자를 분리한 비교 기준 | 별도 작업 메모에 seed 0 공식 test 0.9230 기록 |
| [E1a](CNN_UCI_HAR_E1a.ipynb) | BatchNorm·Dropout·EarlyStopping으로 과적합 억제 | 별도 메모에 seed 0 공식 test 0.9223 기록 |
| [E1b](CNN_UCI_HAR_E1b.ipynb) | Flatten을 GlobalAveragePooling으로 교체 | 별도 메모에 seed 0 공식 test 0.9192 기록 |
| [E1c](CNN_UCI_HAR_E1c.ipynb) | CNN 뒤 LSTM 헤드로 시간 순서 요약 | 저장된 실행 출력 및 확정 비교 없음 |
| [S0](CNN_UCI_HAR_S0.ipynb) | SIT/STAND 검증 비교의 기준 CNN | 저장된 실행 출력 및 확정 비교 없음 |
| [S1](CNN_UCI_HAR_S1.ipynb) | 학습 센서 신호의 ±15° 회전 증강 | 저장된 실행 출력 및 확정 비교 없음 |
| [S1c](CNN_UCI_HAR_S1c.ipynb) | 작은 CNN+LSTM과 회전 증강 결합 | 별도 메모에 seed 0 validation 0.9454 기록 |
| [S2](CNN_UCI_HAR_S2.ipynb) | 기울기 차이가 작은 학습 피험자의 SIT/STAND 가중치 조정 | 저장된 실행 출력 및 확정 비교 없음 |
| [S3](CNN_UCI_HAR_S3.ipynb) | CNN의 SIT/STAND 예측만 501개 움직임 특징으로 재판정 | 저장된 실행 출력 및 확정 비교 없음. 수작업 특징을 쓰는 하이브리드 |

E0→E1a는 규제로 검증 손실의 최저 시점이 늦어졌지만 seed 0의 공식 test 정확도는 0.07%p 낮았습니다. E1a→E1b는 파라미터가 크게 줄고 동적 행동의 상호 오류가 줄었지만, `SITTING`↔`STANDING` 오류는 160→187개로 늘었습니다. 이 값들은 **드라이브의 `UCI_HAR_프로젝트_정리.md`에 남은 단일 시드 메모**에서 옮긴 것으로, 해당 E 노트북 파일에는 실행 출력이 저장되어 있지 않습니다. 시드 간 변동을 확인하지 못했으므로 인과적 결론으로 해석하지 않습니다.

S1c 메모의 0.9454는 피험자 5·11·17·23·29를 대상으로 한 **검증 정확도**입니다. 핵심 피험자 5·17의 SIT/STAND 정확도는 0.7975였습니다. E 계열의 **공식 test 정확도**와 같은 표본에서 비교한 값이 아닙니다. S0·E1c의 동일 검증 결과가 없으므로 회전 증강의 개선 여부도 판단할 수 없습니다. 어느 실험이 최종 최고 성능인지 아직 확정하지 않았습니다.

## 재실행과 후속 검증

- Colab에서 필요한 패키지와 `DATA/UCI-HAR Dataset`을 준비하고 각 노트북의 `DATA_PATH`를 실제 경로로 맞춥니다. 데이터와 가중치는 저장소에 올리지 않습니다.
- 단계별 셀을 위에서 아래로 실행합니다. E0·E1a·E1b는 seed 0·1·2를 따로 기록하되, 당시 코드가 공식 test도 계산하므로 새 모델 선택 근거로 사용하지 않습니다.
- S0·S1·S1c·S2·S3 및 E1c는 같은 검증 피험자에서 전체 Accuracy·Macro F1과 5·17번의 SIT/STAND 정확도를 비교합니다. 나머지 11·23·29번과 클래스별 오류도 함께 봅니다.
- 각 시드의 지표, 평균·표준편차, 학습 곡선과 혼동 행렬을 저장한 뒤 검증 성능으로 최종 방식을 선택합니다. 그 다음에만 해당 노트북의 `FINAL_TEST` 보호 셀을 의도적으로 실행해 공식 test 성능을 기록합니다.

현재 업로드한 E/S 노트북은 코드 구조와 해설의 보존본입니다. 드라이브에 있던 원본 자체에 출력이 없으므로 이 저장소의 새 노트북에도 실행 결과를 만들어 넣지 않았습니다.

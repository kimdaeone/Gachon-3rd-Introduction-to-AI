이번 실험에서 뚜렷했던 차이는 비교 상대와 평가 사용자에 따라 달랐다. Inception을 적용한 B1은 A1보다 개발에서 개선됐고, 파라미터가 가장 적은 B4는 사전에 정한 성능 유지 기준을 충족했다. 보류 사용자 6명에서는 기본 CNN인 A0가 가장 높았다.

연구 질문에 대한 답

Q1. Inception과 residual의 결합

residual을 쓴 모델에서 일반 합성곱을 Inception으로 바꾼 B1은 A1보다 평균 +0.81%p, 5/5 fold 개선됐다. B1−A0는 +0.33%p(3/5), B1−A2는 −0.02%p(3/5)로 모두 사전 기준상 구별 불가였다. 결합 효과의 보조 지표 (B1−A2)−(A1−A0)는 평균 +0.47%p였으며 fold별 방향은 달랐다.

Q2. SE와 CBAM의 추가 효과

B1 대비 SE는 −0.38%p, CBAM은 −0.17%p였고, 각각 2/5 fold만 개선돼 사전 기준상 구별 불가였다. B3−B2 역시 +0.21%p(2/5)였다. 두 구조는 채널 attention 계산도 달라 CBAM의 시간 attention만 비교하려면 B3와 B3-C의 직접 비교가 필요하다.

Q3. Depthwise 경량화

B1을 Depthwise 구조로 바꾼 B4는 개발 Macro F1이 0.38%p 낮고 파라미터가 56.9% 적었다. 손실이 1.0%p 이내이고 파라미터가 감소해 사전 기준의 경량화 유지를 충족했다. 같은 CPU에서 지연시간 중앙값은 1.2% 감소했다.

결과를 해석할 때의 한계

  • 보류 사용자 6명. A0와 A2의 순위가 바뀐 결과는 이 사용자 구성에서 관측됐다. seed 표준편차는 같은 6명에서 학습을 반복했을 때의 변동만 보여준다. 다른 사람, 기기, 휴대 위치와 일상 환경에서의 성능은 별도로 확인해야 한다.
  • 개발 점수와 모델 선택. 같은 검증 fold로 CNN 학습 종료 epoch를 고르고 점수를 계산했다. 모델 선택에도 그 점수를 썼기 때문에 개발 점수에는 선택의 영향이 있다. RF에는 epoch 선택이 없었다. fold마다 학습 사용자가 겹치며 seed 반복은 같은 검증 사용자를 평가한다.
  • 판정 기준과 구조 비교. 개선·악화·경량화 유지는 연구 전에 정한 실용 기준이다. 통계적 검정을 별도로 수행해야 유의성이나 비열등성에 대해 판단할 수 있다. Inception을 도입하면 파라미터 수와 한 출력이 참조하는 입력 범위도 달라진다.
  • 데이터 및 장비 조건. 초기 품질·라벨 분포 분석에는 전체 데이터를 살폈고, 학습과 개발 검증에서는 보류 사용자 6명을 제외했다. CPU 결과는 사용한 PC와 라이브러리, 입력·스레드 설정에서 관측한 수치다.

완료 범위와 후속 실험

필수 CNN 개발 검증 105회, RF 개발 검증 15회, CNN 7종 CPU 측정, A2·A0·RF 보류 평가 9회를 완료했다. 선택 2단계(B5·B6·A3·A4·A5)는 추가 75회에 필요한 실행 자원 배정을 보류했다. B3−B2가 사전 개선 기준인 평균 +0.5%p 이상 및 4/5 fold 이상을 충족하지 않아 조건부 B3-C는 실행을 생략했다. B6-C는 2단계에서 B6의 개선 여부를 확인한 뒤 같은 기준으로 결정한다. 1단계 실행계획과 완료 기록

  1. 개발 데이터에서 걷기와 계단 행동의 혼동을 사용자별로 확인한다. 클래스 가중치, 데이터 증강, 윈도우 길이는 하나씩 바꾸고 같은 분할과 seed에서 비교한다.
  2. 변경된 설정은 새로운 보류 사용자나 독립 데이터에서 평가한다. 사용자와 휴대 위치가 달라져도 Recall과 사용자별 정확도가 유지되는지 확인한다.
  3. 경량화가 목적이면 B1과 B4를 목표 기기에서도 측정한다. 단일 윈도우 처리 시간과 함께 데이터 정제와 특징 변환을 포함한 전체 지연시간을 기록한다.

재현 방법과 실행 기록

아래 명령은 저장소 루트에서 실행한다. 원본 WISDM 아카이브는 기본 경로 DATA/WISDM/WISDM_ar_latest.tar.gz를 사용한다. 경로를 바꾸려면 --archive를 하위 명령 앞에 둔다. 기존 개발 실행 기록, 노트북과 가중치를 함께 준비하고, refit과 evaluate는 GPU가 연결된 런타임에서 실행한다.

python 9week/scripts/final_wisdm.py freeze
python 9week/scripts/final_wisdm.py refit
python 9week/scripts/final_wisdm.py evaluate
python 9week/scripts/benchmark_wisdm.py
python 9week/scripts/report_final_wisdm.py

freeze는 완료된 개발 기록을 검증하고 후보와 설정을 고정한다. refit은 개발 30명으로 다시 학습하고 evaluate는 저장된 모델을 보류 6명에 적용한다. PC에서 CPU 벤치마크를 실행한다. 마지막 스크립트는 저장된 예측과 체크포인트를 검증해 지표와 보고서를 다시 만든다.

최종 CNN 재학습은 Tesla T4, Python 3.13.16, TensorFlow 2.21.0, Keras 3.13.2, NumPy 2.4.6에서 실행했다. 최종 RF는 같은 런타임의 CPU와 scikit-learn 1.6.1을 사용했고, 개발 RF 재현에는 scikit-learn 1.9.1을 사용했다.

첫 Colab 실행에서는 재학습 진행까지 관측했다. 런타임 종료 이후에는 상태를 확인할 수 없었으며 그 첫 실행의 테스트 시작 기록은 관측되지 않았다. 대체 T4에서 같은 고정 설정으로 재개하고 완료된 seed별 산출물을 회수했다. 표준화 값과 재학습 환경 · 런타임 복구 기록

화면 이용과 설계 근거

  • 글자 크기. 제목과 본문의 크기에 루트 글자 크기를 기준으로 하는 rem을 사용해 브라우저 글자 설정을 따르도록 했다. KRDS 타이포그래피
  • 현재 위치와 이동. 탐색 메뉴에 현재 페이지를 표시하고 페이지 목차와 앞뒤 이동 링크를 제공한다. Nielsen Norman Group 사용성 원칙
  • 대비와 터치 영역. WCAG 2.2 AA의 일반 텍스트 대비 기준은 4.5:1이며 큰 텍스트는 3:1이다. 포인터 대상은 원칙적으로 24 × 24 CSS px 이상이며 충분한 간격이나 문장 속 링크 등 예외가 있다. 주요 탐색 항목은 이 프로젝트의 설계 선택으로 높이를 44 CSS px 이상으로 잡았다. WCAG 2.2 최소 대비 · WCAG 2.2 최소 대상 크기

# 11. WISDM 최종 테스트 평가와 CPU 추론시간

[연구계획서](../연구계획서.md)에 따라 개발 30명에서 **A2**를 선택했다. CNN 7개를 동일한 개발 fold 5개 × seed 3개로 비교한 뒤 선택과 학습 epoch를 기록했다. 테스트 사용자 6명에서는 선택 CNN과 A0·RF의 고정된 seed를 평가했다.

## 개발 결과와 최종 설정 고정

동일 모델에서 먼저 seed 3개를 fold별로 평균했다. 표는 fold 5개의 평균과 표본 표준편차를 보여준다. 최고 평균 Macro F1을 기준으로 선택하며, 동점이면 파라미터 수와 모델명 순서를 적용한다. CNN 재학습 epoch는 해당 모델의 개발 best epoch 15개의 중앙값을 반올림해 고정했다.

| --- | --- | --- | --- |
| A2 | 0.8964 ± 0.0374 | 36,806 | 15 |
| B1 | 0.8962 ± 0.0482 | 36,806 | 21 |
| B3 | 0.8945 ± 0.0399 | 39,028 | 15 |

같은 개발 fold에서 RF 참조선의 Macro F1은 0.7683 ± 0.0578였다. 개발 구조 비교와 사전 판정은 [1단계 개발 검증 종합](10_1단계_개발_검증_종합.md)에 정리했다.

B3는 B2보다 평균 +0.21%p, 2/5 fold에서 개선됐다. 사전 기준에 따라 B3-C 학습 단계는 생략했다.

개발 결과와 소스·입력 해시는 2026-11-20T00:57:56+00:00 (UTC)에 [선택 기록](../final/selection.json)으로 보존했다. 테스트 평가 시작은 2026-11-20T01:06:20+00:00 (UTC)이다.

## 최종 재학습과 테스트 조건

- 개발 사용자 30명의 정제된 데이터에서 stride 64로 **12,685개** 학습 윈도우를 만들었다. CNN 표준화는 이 30명의 원본 축별 표본으로 다시 계산했다. Adam 0.001, batch 64, 고정 epoch를 사용했다.
- RF는 stride 64 윈도우의 원본 스케일에서 통계 특징 47개를 계산했고, 고정 설정의 트리 300개로 다시 학습했다.
- 사용자 6, 21, 24, 27, 29, 34의 128 × 3 입력에서 stride 128로 테스트 윈도우 **1,411개**를 구성했다. 각 모델의 seed 0·1·2를 동일한 윈도우에서 평가했다.
- CNN 재학습은 Tesla T4, Python 3.13.16, TensorFlow 2.21.0, Keras 3.13.2, NumPy 2.4.6에서 실행했다. CNN 평가에는 Tesla T4, TensorFlow 2.21.0을 사용했다. RF 재학습과 평가는 같은 런타임의 CPU에서 scikit-learn 1.6.1으로 실행했다. 개발 RF 재현 기록의 scikit-learn은 1.9.1이다. [표준화 값 및 실행 환경](../final/refits/development.json)

첫 최종 실행의 마지막 확인 상태는 재학습 진행이었다. Colab 런타임이 종료돼 마지막 확인 이후의 상태는 확인할 수 없었고, 해당 런타임의 테스트 시작 기록은 관측되지 않았다. 대체 T4에서 동일한 고정 설정으로 재개하고 완료된 seed의 산출물을 실행 중에 회수했다. [런타임 복구 기록](../final/runtime_recovery.json)

## CPU 추론시간

AMD Ryzen 7 7730U with Radeon Graphics PC에서 TensorFlow 2.22.0-rc0, Keras 3.16.0.dev2026101104, CPU intra-op·inter-op 각 1스레드, 배치 1, float32 입력 (1, 128, 3)을 사용했다. oneDNN은 모든 모델에서 비활성화했다. CNN 7개에 동일한 합성 입력과 각 모델의 개발 fold 0·seed 0 가중치를 적용했다. 모델마다 50회 워밍업 후 200회씩 5차례 호출했다. 측정은 컴파일된 모델 호출과 NumPy 출력 변환을 포함한다. 가중치 로딩과 전처리는 측정 범위 밖이다. 각 모델의 1,000회 호출에서 중앙값과 사분위수를 계산했다.

| 모델 | 파라미터 | 중앙값 (ms) | Q1–Q3 (ms) | IQR (ms) |
| --- | --- | --- | --- | --- |
| A0 | 84,870 | 0.499 | 0.474–0.535 | 0.061 |
| A1 | 84,870 | 0.522 | 0.486–0.567 | 0.081 |
| A2 | 36,806 | 0.634 | 0.593–0.671 | 0.078 |
| B1 | 36,806 | 0.643 | 0.602–0.686 | 0.085 |
| B2 | 38,998 | 0.658 | 0.625–0.713 | 0.088 |
| B3 | 39,028 | 0.723 | 0.680–0.764 | 0.085 |
| B4 | 15,878 | 0.635 | 0.593–0.674 | 0.082 |

B1 대비 B4의 파라미터 수 변화는 -56.9%, CPU 중앙 지연시간 변화는 -1.2%였다.

## 해석 범위

사전 개선·악화·경량화 유지 판정은 개발 fold 비교에 적용한다. 테스트는 사용자 6명의 고정된 사례이므로 더 넓은 모집단의 성능이나 기기·휴대 위치 변화에 대한 일반화에는 한계가 있다. seed 간 표준편차에는 새 사용자 표본의 불확실성이 포함되지 않는다. 연구 초기에는 전체 데이터의 품질과 라벨 분포를 살폈다. CPU 지연시간은 이 장비와 실행 조건에 한정된다.

## 재현
